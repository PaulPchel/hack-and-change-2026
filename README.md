# МТС Energytool: ИИ-консультант для сайта

Чат-бот, который выясняет задачу клиента, подбирает продукты Energytool по базе знаний
и формирует заявку для менеджера. Проект для хакатона Hack&Change 2026.

## Быстрый запуск (Docker)

1. Положите `knowledge-base.zip` в папку `data/` (в репозитории базы нет, она из материалов кейса).
2. Скопируйте настройки и впишите ключ:
   ```bash
   cp .env.example .env
   ```
   В `.env` заполните `LLM_BASE_URL` и `LLM_API_KEY`.
3. Запустите:
   ```bash
   docker compose up --build
   ```
4. Откройте http://localhost:8000

Без ключа чат всё равно запустится, но ответит заготовкой (режим заглушки).

## Как проверить основной сценарий

1. На вкладке «Чат» опишите задачу, например: «У нас выросли счета за электричество».
2. Ответьте на уточняющие вопросы бота и согласитесь оставить заявку: ФИО, телефон, компания (только тестовые данные).
3. Включите «Режим отладки»: под ответами появятся время ответа, выполненные шаги (поиск, модель и т. д.) и документы базы знаний.
4. «Новый диалог» сбрасывает контекст. Старые диалоги видны на вкладке «История», в том числе без заявки.
5. Вкладка «Заявки»: все сформированные заявки с резюме диалога.

## Архитектура

```
Браузер (static/index.html)
   │  /api/chat, /api/session, /api/sessions, /api/leads
FastAPI (app.py) ──► consultant.answer(history)  ──► retrieval.search(query) ──► база знаний
   │                        └── LLM по API организаторов
SQLite (db.py): сессии, сообщения, заявки → storage/app.db
```

- `app.py` принимает сообщения, вызывает консультанта, замеряет время, сохраняет всё в базу.
- `consultant.answer(history)` возвращает `{"text", "sources", "lead", "trace"}`: ответ, имена файлов базы, заявку (или `None`) и необязательный список шагов `[{"step", "ms", "note"}]` для режима отладки. Собирать шаги помогает `tracing.py`.
- `solution.py` — отдельная точка входа для автоматической проверки (читает вопросы, пишет `submission.csv`).
- `stub_consultant.py` работает, пока нет `consultant.py`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | адрес и ключ API языковой модели |
| `LLM_MODEL`, `EMB_MODEL` | модель ответов и модель эмбеддингов |
| `TOP_K` | сколько фрагментов базы передавать модели |
| `DATA_DIR` | папка с `knowledge-base.zip` |
| `DB_PATH` | файл SQLite с историей |
| `USE_STUB` | `1` — всегда использовать заглушку |

Порт: `8000`. Ключи хранятся только в `.env`, который не попадает в git.

## Запуск без Docker

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app:app --port 8000
```

## Известные ограничения

- Заявки не уходят в CRM и на почту: они хранятся в базе и видны на вкладке «Заявки» (так и требует кейс).
- Один диалог — одна заявка: повторная заявка в том же диалоге заменяет предыдущую.
- Используйте только тестовые персональные данные.
