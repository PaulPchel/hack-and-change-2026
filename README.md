# МТС Energytool: ИИ-консультант для сайта

Чат-бот, который выясняет задачу клиента, подбирает продукты Energytool по базе знаний
и формирует заявку для менеджера. Проект для хакатона Hack&Change 2026.

## Что умеет

- Отвечает только по базе знаний. Если ответа в ней нет, прямо говорит об этом.
- Задаёт один уточняющий вопрос, когда не хватает данных о клиенте.
- Не раскрывает производителей оборудования и не даёт юридических оценок.
- Предлагает связаться со специалистом и собирает заявку: ФИО, телефон, компания и резюме диалога.
- Помнит контекст в рамках одного диалога. «Новый диалог» сбрасывает его, старые диалоги сохраняются.
- Режим отладки показывает время ответа, шаги и документы базы знаний.

## Быстрый запуск (Docker)

1. Положите `knowledge-base.zip` в папку `data/` (в репозитории базы нет, она из материалов кейса).
2. Скопируйте настройки и впишите ключ:
   ```bash
   cp .env.example .env
   ```
   В `.env` заполните `LLM_BASE_URL` и `LLM_API_KEY` (доступ к модели выдают организаторы хакатона).
3. Запустите:
   ```bash
   docker compose up --build
   ```
4. Откройте http://localhost:8000

Без ключа можно проверить сбор заявки, отправив «Перезвоните мне». Для ответов по базе нужны настройки модели. Для режима заглушки задайте `USE_STUB=1`.

## Как проверить основной сценарий

1. На вкладке «Чат» опишите задачу, например: «У нас выросли счета за электричество».
2. Ответьте на уточняющие вопросы бота и согласитесь оставить заявку: ФИО, телефон, компания (только тестовые данные).
3. Включите «Режим отладки»: под ответами появятся время ответа, выполненные шаги (поиск, модель и т. д.) и документы базы знаний.
4. «Новый диалог» сбрасывает контекст. Старые диалоги видны на вкладке «История», в том числе без заявки.
5. Вкладка «Заявки»: все сформированные заявки с резюме диалога.

## Архитектура

```
Браузер (static/index.html)
   │  /api/chat, /api/session, /api/sessions, /api/leads
FastAPI (app.py) ──► consultant.answer(history)  ──► solution.Retriever ──► база знаний
   │                        └── LLM по API организаторов
SQLite (db.py): сессии, сообщения, заявки → storage/app.db
```

- `app.py` принимает сообщения, вызывает консультанта, замеряет время, сохраняет всё в базу.
- `consultant.answer(history)` возвращает `{"text", "sources", "lead", "trace"}`: ответ, имена файлов базы, заявку (или `None`) и необязательный список шагов `[{"step", "ms", "note"}]` для режима отладки. Собирать шаги помогает `tracing.py`.
- `solution.py` — отдельная точка входа для автоматической проверки (читает вопросы, пишет `submission.csv`).
- `stub_consultant.py` можно включить через `USE_STUB=1`.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `app.py` | Веб-сервер чата |
| `db.py` | История диалогов и заявки (SQLite) |
| `static/index.html` | Страница чата, истории, заявок и режима отладки |
| `consultant.py` | Правила консультанта, ограничения по темам, сбор заявки |
| `solution.py` | Загрузка и разбиение базы, поиск, вызов модели, точка входа для автопроверки |
| `tracing.py` | Шаги ответа и их время для режима отладки |
| `stub_consultant.py` | Запасной вариант (`USE_STUB=1`) |
| `test_consultant.py` | Тесты консультанта |
| `evaluate_consultant.py` | Прогон демо-вопросов и «ловушек» с сохранением ответов в CSV |
| `Dockerfile`, `compose.yaml`, `.dockerignore` | Запуск одной командой |
| `.env.example` | Пример настроек без ключей |

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | адрес и ключ API языковой модели |
| `LLM_MODEL`, `EMB_MODEL` | модель ответов и модель эмбеддингов |
| `TOP_K` | сколько фрагментов базы передавать модели |
| `DATA_DIR` | папка с `knowledge-base.zip` |
| `DB_PATH` | файл SQLite с историей |
| `USE_STUB` | `1` — всегда использовать заглушку |

Порт: `8000`. Ключи хранятся только в `.env`, который не попадает в git.

## Запуск без Docker

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
set -a && source .env && set +a
uvicorn app:app --port 8000
```

## Проверка консультанта

```bash
python -m unittest -v
python evaluate_consultant.py --reference data/demo_output.csv
```

Для второго запуска задайте `LLM_BASE_URL`, `LLM_API_KEY` и при необходимости `DATA_DIR` в окружении. Файл `demo_output.csv` из материалов кейса положите в `data/`; если примеров ответов нет, запустите команду без `--reference`. Скрипт прогоняет вопросы из `questions.csv` и пять ловушек, сохраняет ответы и метрики стиля в `consultant_evaluation.csv`. Точность фактов и соблюдение ограничений в ответах модели проверяются по CSV вручную.

## Известные ограничения

- Заявки не уходят в CRM и на почту: они хранятся в базе и видны на вкладке «Заявки» (так и требует кейс).
- Для повторной заявки начните новый диалог.
- Используйте только тестовые персональные данные.
